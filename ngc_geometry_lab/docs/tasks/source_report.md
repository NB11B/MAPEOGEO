## Concrete integration surface

Add `ngc_geometry_lab/_vendor/mapeogeo` to the Python import path. These modules require only the Python standard library. Use well-formed finite matrices of compatible dimensions; the upstream functions do not uniformly validate malformed inputs.

| Module | Callable | Contract that can be qualified |
|---|---|---|
| `mapeogeo.psmsl_operator_algebra_v1` | `matmul(A, B)`; `fuse(A, B)` | Matrix product; `fuse(A, B)` returns `B @ A`, preserving execution of A followed by B |
| Same | `information_semantics(A, tol=1e-10)` | Numerical rank/nullity and injective/surjective/invertible/information-loss labels |
| Same | `ordering_semantics(A, B, tol=1e-10)` | Frobenius norm of `AB-BA` and commutation/reordering labels |
| `mapeogeo.psmsl_operator_basis_v1` | `discover_linear_operator_basis(operators, tol=1e-10)` | Greedy linearly independent basis of flattened operator matrices, with redundant indices |
| `mapeogeo.psmsl_work_equivalence_v1` | `work_relative_commutation(A, B, observation=None, tolerance=0.0)` | Whether the requested observation sees the difference between AB and BA |
| Same | `work_relative_information_loss(T, observation_before=None, observation_after=None, tolerance=1e-12)` | Whether `observation_after @ T` preserves the requested original observation map |
| `mapeogeo.psmsl_work_plan_v1` | `derive_plan(operators, tol=1e-10)` | Semantic reordering flags and irreversible indices; its `parallelizable` flag is not a measured parallel backend or speedup |
| `mapeogeo.latent_generator_v1` | `linear_inverse(P, y, tol=1e-9)`; `forward(P, q)` | RREF particular solution, explicit null basis, identifiable rank, residual, and forward projection |
| Same | `sinusoid_generator(amplitude, theta)`; `radial_angular_velocity(amplitude, theta, d_amplitude, d_theta)` | Actual planar amplitude/phase representation and radial/angular derivative decomposition |
| `mapeogeo.latent_generator_observability_v2` | `observability_matrix(A, C, steps=None)` | Stacked `C, CA, ...`; defaults to state dimension steps |
| Same | `trajectory_inverse(Ps, ys)`; `dynamic_initial_state_inverse(A, C, ys)` | Recovery from multiple projections or a linear dynamical observation sequence |

`linear_inverse` returns a particular representative with free variables set to zero. It is not a minimum-norm solver. For `P=((1,1),)` and `y=(1,)`, the representative is `(1,0)`, while the minimum-norm representative would be `(0.5,0.5)`. Its upstream docstring accurately describes the zero-free-variable choice. `source_identified` remains false even for full-rank state recovery, separating coordinate recovery from identification of a physical source.

Fixtures newly generated by this harness must be labeled qualification fixtures; they are inputs to these real upstream operators, not newly discovered repository primitives. Use an independent matrix/SVD or exact rational oracle for correctness. Do not infer runtime parallelism or acceleration from the semantic flags alone.

## Baseline execution and a confirmed false failure

All 18 unchanged, zero-argument upstream test functions were executed directly using `runpy`; they contain no pytest fixtures or decorators. The available primary Python runtime lacked pytest, so this was not a pytest session. Results: **17 passed and 1 upstream assertion failed**. The full trace and matrices are retained in `ngc_geometry_lab/_vendor/mapeogeo/BASELINE_RESULTS.json`.

The failing test is `tests/test_psmsl_work_equivalence_v1.py::test_noncommuting_operators_can_be_equivalent_after_work_projection`. The assertion is incorrect for its own matrices:

```text
A = ((1,0),(0,2)); B = ((1,1),(0,1)); P = ((0,1),)
AB = ((1,1),(0,2)); BA = ((1,2),(0,2))
PAB = PBA = ((0,2),)
```

The upstream implementation returns `exact_equal=False`, `observed_difference=0.0`, and `equivalent_for_work=True`, which agrees with the exact products. An independent NumPy int64 multiplication also confirmed the observed equality. The upstream test instead asserts `not w.equivalent_for_work`. Preserve this source and test unchanged; the harness should state the corrected mathematical expectation and retain this as a test-expectation defect, not an operator defect.

### Hash mismatch explained by line endings

The manifest expects `primitive_characterization.json` to be 24,725 bytes with SHA-256 `daef8d9b650ed20c81b69d0b312bc99a0c6153a50fd911e9957ad6676aca9c95`. The Git blob is 23,940 bytes with SHA-256 `b271da54f03348b7941d8aef22ba41ca93bf8d33e2cbc3461780904aaa4d273f` and contains 785 LF newlines. Replacing those newlines with CRLF yields **exactly the manifest's size and SHA-256**. Thus this apparent integrity failure is a line-ending discrepancy, not evidence of changed characterization content. The raw source remains unchanged. See `AUDIT_FINDINGS.json` for the measured values.
